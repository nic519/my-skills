# 简洁、一致与组件复用

把当前页面作为整个产品的一部分来修改。先理解用户任务、同类页面和已有组件，再决定删什么、统一什么、复用什么。遵循项目约定和用户已确认的方向，不把一次局部美化扩大成全站重做。

## 判断标准

- **简洁**：减少完成任务所需的信息辨认和操作成本。删除重复表达和无意义装饰，保留关键限制、错误反馈、主操作及必要的使用线索。更少的元素不一定更容易使用。
- **全局一致**：相同语义采用相同的视觉层级和交互方式，包括标题、间距、状态、按钮、文件输入和反馈；不同业务允许必要差异。
- **组件复用**：让同类界面的共同规则由同一实现维护。既包括基础控件，也包括跨页面的布局与业务交互模式。

## 修改前：找到产品已有的答案

1. 阅读适用的项目约定，检查当前页面和最相关的同类页面。具备运行环境时查看真实界面；只能阅读代码时，明确视觉结论尚未验证。
2. 搜索现有基础控件、共享布局、业务组件和样式变量。记录本次可复用的组件，以及当前页面偏离已有模式的位置。
3. 按用户任务区分信息：完成任务必需的输入、设置、结果与主操作；必要限制与反馈；高级设置和诊断信息。不要机械地把所有设置都折叠。
4. 确定本次修改范围。默认检查同类页面；修正当前改动涉及的共享组件，并验证其调用方。较大范围的历史不一致单独指出，不顺手全面重构。

已有模式也可能有问题。若它重复、难用或违反用户明确约定，修正相关共享模式，避免为了表面统一复制缺陷。

## 简化界面：先删重复，再调布局

- 同一标题、状态和操作含义只在最合适的位置表达一次。保留解释限制、消除歧义和帮助恢复错误的信息。
- 让用户先看到输入、必要设置、结果和下一步。命令、日志等诊断内容通常放在底部并默认折叠；失败时让关键错误和处理入口可见。
- 用对齐、间距和文字层级组织内容，减少重复卡片、嵌套边框和无意义留白。采用现有间距规则，不为单个页面不断新增数值。
- 宽屏将相关输入合理并排，窄屏自然堆叠。组内紧凑、组间清晰，避免通过压缩点击区域或字号来省空间。
- 检测、刷新等辅助操作靠近所属标题或状态；操作按钮靠近对应输入。避免为小操作独占整行。
- 复制、选择文件等明确的辅助操作可使用图标按钮，并提供可访问名称和提示。主要操作保留文字；图标含义不明确时保留文字。
- 长命令和路径允许换行，复制操作保持可见、复制完整原始内容，并反馈成功或失败。
- 优化空间后，用户仍应看得出如何开始、支持什么输入、当前发生了什么、下一步做什么。不能靠隐藏主操作、拖拽线索或错误提示获得“清爽”。

## 复用组件：按语义选择边界

按以下顺序判断，选择足够解决当前问题的最小改动：

1. **现有组件已能表达需求**：直接复用，不复制一份再改样式。
2. **同一语义缺少一个合理变体**：扩展现有组件，保持默认行为稳定，检查已有调用方。
3. **多个实际场景反复出现同一布局或交互**：提取职责清楚的共享组件，让它集中维护层级、间距、状态和操作位置。
4. **只是外观相似，业务含义或行为不同**：共享基础控件或样式变量，保留业务层差异。

不要为减少代码行数制造大量布尔开关、页面名称分支或万能配置组件；不要为尚不存在的页面预建抽象。新项目没有可复用组件时，先建立当前页面真正需要的基础模式。

共享组件发生变化时，检查受影响页面的真实需求，而不只确认类型兼容。不要让某一页的特殊需求改变其他页面的默认行为。

## 取舍顺序

当目标冲突时，优先保证任务完成、必要反馈和操作可发现性，再协调一致性与视觉密度。

- 删除说明前，判断它是否提供了按钮和标题没有表达的信息。
- 折叠内容前，判断首次使用的人是否仍能完成主任务。
- 统一样式前，判断两处是否真的表达相同语义。
- 提取组件前，判断共享的是稳定规则，还是偶然相似的标记结构。
- 扩大修改前，判断它是否为完成当前任务所必需。

采用项目已有规则；只有缺失且影响本次工作时才补充。不要将案例中的尺寸、组件名、页面顺序或业务限制强加给其他产品。

## 验收与交付

根据改动检查空态、已选内容、处理中、成功和失败状态；检查宽窄窗口、长文本、主要操作和受影响的同类页面。无需为无关状态制造额外测试。

使用适合改动的构建、类型检查或已有测试，并实际查看能运行的界面。布局是否合理不能仅靠构建通过来证明；交互变化不能仅靠截图证明。

简短报告：删减了什么、统一了什么、复用了或提取了什么，以及验证结果。区分构建／测试、浏览器模拟和真实桌面验证；未执行的验证明确说明，不把模拟事件当作原生文件拖拽等系统行为的验证。

当需要理解这些规则的来源或处理文件输入、步骤、诊断区域时，阅读 [字幕鸭案例](references/subtitle-duck.md)。
